# Verification scope and reproducibility

## Project pins

- Lean: `leanprover/lean4:v4.24.0`, commit `797c613eb9b6d4ec95db23e3e00af9ac6657f24b`.
- Mathlib: `v4.24.0`, commit `f897ebcf72cd16f89ab4577d0c826cd14afaafc7`.
- All transitive Lake dependencies: `lake-manifest.json`.
- lean4export: `v4.24.0`, commit `f7f95b22c1bff79cfbec7f32c13ced73a1b4fdcd`.
- nanoda: `68d5ca9db226849b41a6fff59d796ff19d0a8840`.

The exact proof statements are defined in the Mathlib-only `Challenge.lean`; the corresponding theorems are in `Solution.lean`. In particular, abstract nonfreeness is the actual `¬ IsFreeGroup` predicate, not an alias for the existence of a relation.

## Checks actually performed

The following results were supplied with the original research artifact. The
recorded verification date is 2026-10-10. Repository preparation checked the
source hashes against that evidence; subsequent builds should retain their
own logs and run status.

1. `lake build Solution` on the pinned project toolchain.
2. A separate project-directory rebuild with no copied project `.olean` files; the external pinned Mathlib dependency cache was reused.
3. `AxiomAudit.lean`: 22 headline/intermediate declarations, using only `propext`, `Classical.choice`, and `Quot.sound` or fewer.
4. Source scan of delivered Lean modules for proof placeholders, custom axiom declarations, and native compiler decision shortcuts. This scan is an additional diagnostic, not a substitute for kernel checking.
5. `lean4export` of eight explicitly listed declarations and their complete transitive dependencies, followed by independent nanoda checking with `unpermitted_axiom_hard_error = true` and only the three standard axioms permitted. Final result: 18,169 declarations checked with no errors.

The selected export declarations are in `logs/nanoda-theorems.txt`. The large export is reproducible and intentionally omitted; its hash and byte count are in `logs/proof-export-summary.json`. The relative `logs/nanoda-config.json` is regenerated by `scripts/verify-nanoda.sh`.

Ordinary `decide` yields proof terms for kernel checking. The project does not use `native_decide`, `Lean.trustCompiler`, custom axioms, or proof placeholders. It does not claim to eliminate Lean's standard classical foundations.

## Comparator reference and limits

The specification/proof/audit organization was informed by [Anthropic formal-math](https://github.com/anthropics/formal-math), inspected at commit `e1a4e6508154ea59f030480661590a9fe3018011`.

The full reference comparator workflow was **not accepted on the original verification host**. Its pinned comparator (`575674928e239f5bc452aab72d1dd7b0f1326494`) expects primitive `String.ofList`, which does not exist in the pinned Lean 4.24 project. A separate probe on that host found missing kernel Landlock support (ABI 0, whereas the requested landrun sandbox required V9). No checker modification or fake sandbox was used.

The final source distribution does not offer a nonfunctional comparator configuration or claim Palomar acceptance. Its independent mathematical specification, Lean checks, and direct nanoda replay are the actual verification evidence. A proposition-definition challenge is not by itself a same-named theorem challenge for the standard comparator.

## Reproduction scripts

- `scripts/verify.sh`: Lean build, source-token check, and complete printed axiom whitelist check.
- `scripts/bootstrap-checkers.sh`: build the pinned lean4export and nanoda tools using the installed project Lean toolchain and Rust/cargo.
- `scripts/verify-nanoda.sh`: export selected declarations and run independent checking.
- `scripts/make-delivery.py`: package only reviewed source, metadata, scripts, and selected text logs, with file hashes.
- `scripts/check-release.py`: check source hashes, package integrity, metadata consistency, historical axiom logs, and exact finite data without rewriting manuscript outputs.
